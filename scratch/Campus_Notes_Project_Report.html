ABSTRACT

Academic resource exchange across university campuses has traditionally suffered from fragmentation, inefficiency, and lack of quality assurance. College students predominantly rely on ephemeral WhatsApp groups, Telegram channels, or personal cloud drives where documents get easily buried, duplicated, or lost at the end of each academic session. Furthermore, high-achieving students possess little to no incentive to scan and distribute their meticulously written notes.

To overcome these challenges, this project presents the design, architectural engineering, and full-scale implementation of the Campus Notes Exchange Platform: an enterprise-grade, peer-to-peer web and hybrid mobile platform built using the MERN Stack (MongoDB, Express.js, React 19, and Node.js).

Key technical innovations implemented in this system include:

  • Credit-Based Gamification Loop: An incentivization economy where uploaders receive +10 credits for verified academic contributions and +5 passive credits whenever peers download their materials, fueling a self-sustaining sharing ecosystem backed by a campus-wide leaderboard.
  • Multi-Criteria Regular Expression Discovery: A multi-field indexing and regular expression search engine allowing students to filter resources instantly by branch, semester, subject code, unit, and teacher name.
  • Embedded Community Governance: High-performance embedded subdocument schemas for 1-5 star ratings with pre-save automated average calculation hooks, threaded comments, and user-initiated content reporting.
  • Enterprise Security Architecture: 10-round salted Bcrypt password hashing, stateless JSON Web Token (JWT) bearer validation, strict Multer MIME-type file whitelisting with 25MB buffer controls, and real-time user banishment middleware.
  • Hybrid Storage Resilience: Dual-mode storage featuring remote Cloudinary Content Delivery Network (CDN) streaming with an automated fallback to local server disk storage.
  • Hybrid Mobile Preparedness: Clean SPA bundling with Vite, prepared for single-command native compilation to Android .apk containers via Capacitor.

Keywords: MERN Stack, React 19, RESTful API, MongoDB Subdocuments, Gamification, Academic Resource Sharing, JWT Authentication, Cloudinary, Capacitor.

CHAPTER 1: INTRODUCTION & BACKGROUND

1.1 Project Overview

The Campus Notes Exchange Platform is a full-stack, peer-to-peer web and mobile application designed specifically to streamline and centralize academic material distribution across engineering and polytechnic campuses. Built using the modern MERN technology stack, the system serves as an institutional digital repository where students across all academic branches can upload, browse, preview, evaluate, and download curriculum-specific study materials including lecture notes, past exam solutions, lab manuals, and faculty presentations.

1.2 Motivation & Problem Statement

In the contemporary collegiate environment, academic resources remain heavily decentralized. Students primarily exchange notes through private messaging applications such as WhatsApp, Telegram, or Discord. While accessible, these channels introduce critical systemic problems:

  • High Resource Fragmentation: Study materials are scattered across dozens of ad-hoc group chats with no structured indexing. Crucial notes shared in October are virtually unfindable during end-semester exams in December.
  • Lack of Quality Control: Documents are circulated without peer reviews, syllabi verification, or instructor tagging. Students frequently download inaccurate or outdated notes.
  • Zero Contribution Motivation: Top academic performers invest significant effort into crafting handwritten notes, yet they receive neither recognition nor tangible benefit for scanning and sharing their work.
  • Ephemeral Links & Security Hazards: Free cloud links (Google Drive, Mega) frequently expire, hit download quotas, or expose student devices to malicious unvetted executable files.

1.3 Project Objectives

The primary objectives of this project are:

  1. Centralized Academic Taxonomy: Construct an intuitive repository categorized strictly by Department/Branch, Semester (1 to 8), Subject Name, Unit Number, and Faculty Name.
  2. Incentivized Gamification Engine: Implement an algorithmic credit economy awarding contributors +10 credits on note upload and +5 credits upon peer downloads, linked to an institute-wide leaderboard.
  3. Zero-Join Embedded Performance: Leverage MongoDB's flexible document model to embed ratings and threaded comments directly inside note records for sub-50 millisecond read queries.
  4. Enterprise-Grade Security: Secure the application using 10-round salted bcrypt password hashing, stateless JSON Web Tokens (JWT), strict MIME-type sanitization (25MB limit), and instant user banishment middleware.
  5. Hybrid Storage Resilience: Ensure 100% operational uptime by pairing Cloudinary remote CDN media management with an automated local disk storage fallback.
  6. Cross-Platform Mobile Ready: Structure the React client to compile into native Android .apk packages via Capacitor.

CHAPTER 4: SYSTEM DESIGN & ARCHITECTURAL ENGINEERING

4.1 Three-Tier Client-Server Architecture

The system is architected around a strict decoupled Three-Tier pattern:

  1. Presentation Tier (Frontend): Built with React 19 and Vite. State is managed reactively through React Hooks and Context APIs. Axios executes asynchronous HTTP requests, with request interceptors injecting JWT bearer tokens stored in localStorage.
  2. Application Tier (Backend Logic): Implemented using Node.js and Express.js. Business logic is organized modularly into Controllers, Routes, and Middlewares (Auth, Admin, Upload).
  3. Data & Storage Tier: MongoDB provides document storage via Mongoose schemas. Document assets (PDFs/Images) are handled via Cloudinary remote CDN or local file storage.

CHAPTER 5: DATABASE DESIGN & SCHEMA SPECIFICATIONS

5.1 NoSQL Document Modeling Strategy

Unlike relational databases that mandate normalized tables connected via expensive SQL JOIN queries, MongoDB facilitates Embedded Subdocuments. In academic resource sharing, ratings and comments are always queried together with the parent note. By embedding ratings and comments directly inside the Note document, database operations achieve single-query retrieval with sub-50ms latency.

CHAPTER 6: SYSTEM IMPLEMENTATION & CORE MODULES

6.1 Note Upload & Hybrid Storage Engine

The upload engine handles high-volume binary uploads while maintaining system stability. File streams are received through Multer. The backend tests if Cloudinary environment keys exist; if present, the buffer streams to the cloud CDN. Otherwise, it writes directly to server/uploads/, providing bulletproof reliability during offline college LAN testing.

// uploadMiddleware.js: Whitelist Filter & Memory Buffer Setup
const multer = require('multer');
const path = require('path');

const fileFilter = (req, file, cb) => {
  const allowedExtensions = /pdf|ppt|pptx|jpg|jpeg|png/;
  const extname = allowedExtensions.test(path.extname(file.originalname).toLowerCase());
  const mimetype = allowedExtensions.test(file.mimetype);

  if (extname && mimetype) {
    cb(null, true);
  } else {
    cb(new Error('Validation Error: Only PDF, PPT, PPTX, and Image files are permitted!'), false);
  }
};

const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 25 * 1024 * 1024 }, // 25 Megabytes strict limit
  fileFilter
});
module.exports = upload;

6.2 Multi-Criteria Regex Search Engine

To enable lightning-fast discovery, the note querying controller utilizes MongoDB's $regex evaluation across multiple fields simultaneously:

// noteController.js: Dynamic Multi-field Regular Expression Search
exports.getNotes = async (req, res) => {
  try {
    const { search, branch, semester, subject } = req.query;
    let query = {};

    if (branch) query.branch = branch;
    if (semester) query.semester = semester;
    if (subject) query.subject = subject;

    if (search) {
      const searchRegex = new RegExp(search, 'i');
      query.$or = [
        { title: searchRegex },
        { subject: searchRegex },
        { description: searchRegex },
        { teacherName: searchRegex },
        { tags: { $in: [searchRegex] } }
      ];
    }

    const notes = await Note.find(query)
      .populate('uploadedBy', 'name email branch')
      .sort({ createdAt: -1 });
    res.json(notes);
  } catch (err) {
    res.status(500).json({ message: 'Server error retrieving notes' });
  }
};

6.3 Gamification & Credit Incentive Loop

The gamification mechanism solves the student reluctance to share study materials. Credits are awarded via atomic database updates, driving healthy academic competition across departments.

Figure 6.1: The Gamification Contribution Cycle

  • Upload Incentive: When a user uploads a note, their profile is credited with +10 credits.
  • Download Royalty: When a peer downloads that note, the author passively receives +5 credits, rewarding creators of high-quality, popular materials.
  • Leaderboard Ranking: The leaderboard displays top academic contributors, inspiring campus recognition.
// noteController.js: Credit Allocation Hook on Download
exports.downloadNote = async (req, res) => {
  const note = await Note.findById(req.params.id);
  if (!note) return res.status(404).json({ message: 'Note not found' });

  note.downloads += 1;
  await note.save();

  // Passive credit dividend for note author (if not downloading own note)
  if (note.uploadedBy.toString() !== req.user._id.toString()) {
    await User.findByIdAndUpdate(note.uploadedBy, { $inc: { credits: 5 } });
  }

  res.json({ fileUrl: note.fileUrl });
};

6.4 Automated Rating Recalculation Hook

To eliminate expensive average calculations on catalog pages, Mongoose executes a pre-save hook whenever the ratings subdocument array is modified:

// Note.js: Pre-Save Trigger for Running Average Calculation
noteSchema.pre('save', function(next) {
  if (this.isModified('ratings') && this.ratings.length > 0) {
    const sum = this.ratings.reduce((acc, curr) => acc + curr.score, 0);
    this.averageRating = Number((sum / this.ratings.length).toFixed(1));
  } else if (this.ratings.length === 0) {
    this.averageRating = 0;
  }
  next();
});

CHAPTER 7: SECURITY PROTOCOLS & INTEGRITY ENFORCEMENT

7.1 Salted Password Hashing via Bcrypt

Plaintext passwords are never stored in the database. When a student registers or modifies their password, a Mongoose pre-save hook intercepts the document, generates a 10-round cryptographic salt using bcryptjs, and replaces the plaintext input with a secure 60-character one-way hash.

7.2 Stateless JWT Token Lifecycle

User sessions are managed entirely via stateless JSON Web Tokens. Upon successful authentication, the server cryptographically signs a payload containing the user's ID using an HMAC SHA-256 algorithm with a secret key. Outgoing client requests pass this signature via the Authorization: Bearer <token> header.

7.3 Instant Banishment Validation

A frequent flaw in stateless JWT architectures is the inability to revoke access before token expiration. To solve this, our custom authMiddleware performs real-time database validation on every request:

// authMiddleware.js: JWT Validation with Real-Time Banishment Guard
const jwt = require('jsonwebtoken');
const User = require('../models/User');

module.exports = async (req, res, next) => {
  let token = req.header('Authorization')?.replace('Bearer ', '') || req.query.token;
  if (!token) return res.status(401).json({ message: 'Access Denied: No Token Provided' });

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    const user = await User.findById(decoded.id).select('-password');

    if (!user) return res.status(401).json({ message: 'User account no longer exists' });
    if (user.isBanned) return res.status(403).json({ message: 'Account Suspended: Contact College Administrator' });

    req.user = user;
    next();
  } catch (err) {
    res.status(401).json({ message: 'Invalid or Expired Authentication Token' });
  }
};

7.4 Role-Based Access Control (RBAC)

Sensitive administration operations (e.g., banning offending students, wiping abusive files, and inspecting reported items) are protected by adminMiddleware.js, which verifies that req.user.role === 'admin' before allowing route execution.

CHAPTER 10: CONCLUSION & FUTURE SCOPE

10.1 Conclusion

The Campus Notes Exchange Platform successfully addresses the critical issues of resource fragmentation, lack of organization, and absent contribution incentives across college campuses. By combining the high performance of the MERN stack with credit-based gamification, embedded review mechanics, and hybrid mobile deployment, the platform transforms academic material sharing from unorganized group chats into a structured, self-sustaining educational repository.

The system was completely designed, developed, tested, and validated during the industrial internship at Sortiq Solutions Pvt. Ltd. under the guidance of academic and industry mentors. The extensive test suite demonstrates that the application achieves sub-50ms query response times, robust defense against malicious file uploads, and continuous operational availability over campus local area networks.

10.2 Future Scope & Roadmap

While the present release provides a solid foundation, several exciting enhancements are planned for future versions:

  1. AI-Powered Note Summarizer: Integrating Large Language Models (LLMs) to automatically generate bulleted revision summaries, key formulas, and exam flashcards from uploaded PDF files.
  2. Optical Character Recognition (OCR) Search: Employing OCR engines (such as Tesseract.js) to extract handwritten text from scanned notebook images, allowing students to search inside handwritten notes.
  3. Real-Time Push Notifications: Implementing WebSockets or Firebase Cloud Messaging (FCM) to alert students whenever new notes are posted for their enrolled subjects.
  4. Campus Perk Redemption Store: Partnering with college cafeterias, print shops, and stationery stores to allow students to redeem earned gamification credits for academic supplies and discounts.
